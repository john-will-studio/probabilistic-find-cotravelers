# Runners

## analyze.py (single scenario)

`python scripts/analyze.py DATA.csv [MORE.csv ...] --out OUTPUT [--movers ID ...] [--link-ids] [--model A|B|C] [--radius M] [--bias-floor M] [--crowd-radius M] [--gap-seconds S] [--window-seconds S] [--sparse-seconds S] [--lag-seconds S] [--assume-tz ZONE]`

Required columns: `mover_id,timestamp,longitude,latitude,error_radius_m,error_probability` (WGS84 decimal degrees, metres; `error_probability` is the declared enclosed probability of the circular Gaussian). Timestamps need a UTC offset or `--assume-tz`; otherwise they are quarantined with an explicit message. IDs are read as literal strings (`NA`, `NULL` survive). Dependencies: Python 3.12 or 3.14, NumPy, pandas (2.2 or 3), SciPy.

Pipeline: validate and quarantine rows; canonicalise times (unit-independent epoch seconds); deduplicate; split observations into spatially disconnected regions (0.1 degree cells, antimeridian aware) so a distant or erroneous fix cannot veto a dataset, each region with its own local projection; regions wider than 1 degree (coastlines, flight corridors) are cut into overlapping 0.5 degree tiles with a 0.1 degree margin, each with its own projection, and duplicate events from tile overlaps are removed; fit motion per mover in `--window-seconds` windows (default 900; needs 3 fixes, 180 s span, no gap over `--gap-seconds`); pair windows with a KD-tree (focal-first when `--movers` is given; windows too uncertain to ever reach p>=.015 are excluded so one outlier cannot inflate every search); for moving pairs proximity is re-judged at both ends of the shared interval with velocity-fit uncertainty so overtaking is not co-travel.

Sparse or bursty cadence (no window can resolve motion) is covered by point-pair evidence: two fixes from different movers within `--sparse-seconds` whose positions are consistent with `--radius` given both error models, discounted by how many unrelated movers share the place and time, one best match per pair per window. `--sparse-seconds 0` disables it. `--lag-seconds L` (needs `--movers`) shifts the focal clocks so a follower trailing by L seconds lines up.

Models A/B/C: uncertainty only, joint motion, joint motion plus crowd discount (`1/(1+crowd)`, an empirical proxy, not a likelihood ratio; it makes crowded true companions hard to accept, which is why `sweep.py` also tries model B and relies on the null for background). Scores are heuristic and uncalibrated. Pair acceptance (`accepted`) is a fixed screening rule: at least two UTC days, score >= 70, typical episode quality >= .4. It is a default for dense multi-day data; for single-day, sparse or short records use `sweep.py` significance instead of `accepted`. `pair_scores.csv` reports `co_travel`, `co_dwell`, `proximity` and `sparse` episode counts: dwell-dominated pairs share places, not journeys.

`--movers` selects pairs containing either supplied ID (original or namespaced); unknown IDs fail loudly; background movers always remain. It does not specify an exact pair. Absence of a result is insufficient candidate evidence, not proof of independence. Multiple files are namespaced by file name (full path if basenames collide). Stale outputs in the target folder are removed first.

## sweep.py (parallel scenarios plus null)

`python scripts/adapt.py RAW.csv --out DATA.csv --id COL --time COL --lon COL --lat COL --error-m M [--assume-tz UTC] [--where QUERY] [--id-regex RE]` maps any tabular tracking file to the schema in chunks; accuracy is a declared assumption written to `DATA.csv.adapt.json`, never guessed.

`python scripts/sweep.py DATA.csv --out OUT [--movers ID ...] [--lags 0 60 300] [--replicates 8] [--workers N] [--grid-json FILE] [--alpha .05]`

Default grid: radii of 1.5x/3x/6x median error radius (plus 100 m) x time tolerances of 1x/3x/10x median cadence, window length scaled to cadence, model B at the middle radius, one block per lag. Each null replicate circularly shifts every mover's clock independently (whole days plus up to 3 h jitter when the span allows, so time of day is roughly kept but two companions essentially never share a shift), then reruns the whole grid. For every scenario the observed score is converted to a p-value against that scenario's own null scores (leave-one-replicate-out); a pair's statistic is its minimum p across scenarios; `null_p` is the share of null pairs with a statistic at least as extreme; `null_q` is Benjamini-Hochberg over scored pairs. Resolution is limited by replicates x scored pairs, so use more replicates when nothing reaches significance but top pairs look plausible. The null keeps each mover's places and routine but not who-was-where-when, so significance means "more synchronous than independent movers with the same habits", not interaction. Pairs that share a venue schedule at a wide radius can still pass; check `best_radius_m` and `min_radius_m_score70` against the data's error and the operational meaning of close. `sweep_scenario_scores.csv` has every pair x scenario score.

## Limits

Event times are supporting observation bounds. Travel coordinates approximate shared locations, not route geometry. Co-dwell supports stationarity within sampled windows, not continuous occupation. Elliptical errors, 3D/altitude, HSMM and joint-arrival classification are not implemented. Polar data (beyond 80S/83.999N) is refused; MGRS uses WGS84 UTM with Norway/Svalbard exceptions, 100 m grid. Proximity CDF assumes a flat local prior and independent isotropic Gaussian errors. Days are counted by event start date. Focal tiles are processed independently, so a window cut by a tile edge relies on the margin for continuity. Real-data tests used an assumed 50 m @ 95% error for cell data because none was supplied.

References: [SciPy ncx2](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ncx2.html); [NGA MGRS/UTM](https://earth-info.nga.mil/index.php?action=coordsys&dir=coordsys).
