# Runners

## analyze.py (single scenario)

`python scripts/analyze.py DATA.csv [MORE.csv ...] --out OUTPUT [--movers ID ...] [--link-ids] [--model A|B|C] [--radius M] [--bias-floor M] [--crowd-radius M] [--gap-seconds S] [--window-seconds S] [--sparse-seconds S] [--lag-seconds S] [--assume-tz ZONE]`

Required columns: `mover_id,timestamp,longitude,latitude,error_radius_m,error_probability` (WGS84 decimal degrees, metres; `error_probability` is the declared enclosed probability of the circular Gaussian). Timestamps need a UTC offset or `--assume-tz`; otherwise they are quarantined with an explicit message. IDs are read as literal strings (`NA`, `NULL` survive). Dependencies: Python 3.12 or 3.14, NumPy, pandas (2.2 or 3), SciPy.

Pipeline: validate and quarantine rows; canonicalise times (unit-independent epoch seconds); deduplicate; split observations into spatially disconnected regions (0.1 degree cells, antimeridian aware) so a distant or erroneous fix cannot veto a dataset, each region with its own local projection; regions wider than 1 degree (coastlines, flight corridors) are cut into overlapping 0.5 degree tiles with a 0.1 degree margin, each with its own projection, and duplicate events from tile overlaps are removed; fit motion per mover in `--window-seconds` windows (default 900; needs 3 fixes, 180 s span, no gap over `--gap-seconds`); pair windows with a KD-tree (focal-first when `--movers` is given; windows too uncertain to ever reach p>=.015 are excluded so one outlier cannot inflate every search); for moving pairs proximity is re-judged at both ends of the shared interval with velocity-fit uncertainty so overtaking is not co-travel.

Sparse or bursty cadence (no window can resolve motion) is covered by point-pair evidence, classified by each fix's own track: both fixes provably moving = `sparse_travel` (journey), both provably stationary = `sparse_dwell`, a moving fix beside a stationary one = passing (ignored), anything else = `sparse_colocation` (motion unknown, kept as journey-eligible). Moving fixes sampled at different instants are compared after advecting each to a shared reference time with its own track velocity (velocity error added to the variance), so asynchronous sampling of two vehicles at the same speed still matches. Evidence: two fixes from different movers within `--sparse-seconds` whose positions are consistent with `--radius` given both error models, discounted by how many unrelated movers share the place and time, one best match per pair per window. `--sparse-seconds 0` disables it. `--lag-seconds L` (needs `--movers`) shifts the focal clocks so a follower trailing by L seconds lines up.

Models A/B/C: uncertainty only, joint motion, joint motion plus crowd discount (`1/(1+crowd)`, an empirical proxy, not a likelihood ratio; it makes crowded true companions hard to accept, which is why `sweep.py` also tries model B and relies on the null for background). Scores are heuristic and uncalibrated. Pair acceptance (`accepted`) is a fixed screening rule: at least two UTC days (one when the data span a single day), score >= 70, typical episode quality >= .4. It is a default for dense multi-day data; for single-day, sparse or short records use `sweep.py` significance instead of `accepted`. `pair_scores.csv` reports `confidence_score` (all co-location evidence) and `travel_confidence_score` (journey evidence only; provable dwell excluded), with `accepted` and `accepted_travel`, and `co_travel`, `co_dwell`, `proximity` and `sparse` episode counts: dwell-dominated pairs share places, not journeys (`dwell_only` marks pairs whose evidence is entirely co-dwell, e.g. colleagues in one building; treat as place-sharing, not travel).

`--movers` selects pairs containing either supplied ID (original or namespaced); unknown IDs fail loudly; background movers always remain. It does not specify an exact pair. Absence of a result is insufficient candidate evidence, not proof of independence. Multiple files are namespaced by file name (full path if basenames collide). Stale outputs in the target folder are removed first.

## sweep.py (parallel scenarios plus null)

`python scripts/adapt.py RAW.csv --out DATA.csv --id COL --time COL --lon COL --lat COL --error-m M [--assume-tz UTC] [--where QUERY] [--id-regex RE]` maps any tabular tracking file to the schema in chunks; accuracy is a declared assumption written to `DATA.csv.adapt.json`, never guessed.

`python scripts/sweep.py DATA.csv --out OUT [--movers ID ...] [--lags 0 60 300] [--replicates 8] [--workers N] [--grid-json FILE] [--alpha .05]`

Default grid: radii of 1.5x/3x/6x median error radius plus 100 m and 250 m x time tolerances of 1x/3x/10x median cadence, window length scaled to cadence, model B at the middle radius, one block per lag (override with `--grid-json`; widen it when the data's plausible "close" is larger). The whole grid is run on the observed data and on `--replicates` null copies (default 20, the minimum at which alpha .05 is reachable).

Null: with at least 4 UTC days (`--null auto`), each day's tracks are reassigned among the movers active that day by an independent random permutation (`day_permute`). Observation times, places, cadence and crowding stay exactly as observed; only who-travelled-with-whom and its recurrence across days is scrambled. Shorter data use `time_shift`: every mover's clock is circularly shifted by its own continuous random amount (this moves bursty observation windows, so it is a weaker null). Neither null can tell a companion from a stranger who keeps the same schedule and venue; it measures recurrence beyond individual habits.

Statistic: every scenario score is converted to a p-value against that scenario's pooled scores from the other datasets (observed plus nulls scored symmetrically, so the observed data is exchangeable with each null under no signal); a pair's statistic is its smallest scenario p-value. `fwer_p` = (1 + number of null replicates whose best pair statistic anywhere is at least as extreme) / (1 + replicates): a family-wise p-value that prices in scenario selection, the number of pairs searched and unscored pairs. `significant` uses only crowd-adjusted (model C) scenarios and `fwer_p <= alpha`; `significant_travel` applies the same test to the journey-only statistic and is the right call for "travelling with" (co-workers who share a building score on the first statistic but not the second). `significant_any_model` also lets the uncrowded model vote (more recall in busy places, more schedule-synchronised strangers). An independent audit found `significant` too conservative on dense commuter data (0 of 4 planted pairs) where `significant_any_model` found 4 of 4 with no false positives: always read both columns, and report which one supports a finding. Validation on synthetic crowded nulls (40 movers in a 3 km box, 6 days, no companions): 0 of 40 datasets had any significant pair; with one planted companion 20 of 20 were found. These are fixture-specific, not a guarantee on real data, and custom grids or very different data should be re-checked with a no-companion control. Pairs that share a venue schedule at a wide radius can still pass; check `best_radius_m` and `min_radius_m_score70` against the data's error and the operational meaning of close. `sweep_scenario_scores.csv` has every pair x scenario score.

## Memory

See README, "Memory and Windows". Summary: `sweep.py` sizes workers to a memory budget (`--max-memory-gb`), slims the data it copies to workers, supports Windows (`spawn`), and has a watchdog that stops the run cleanly if the budget is exceeded. `analyze.py` reads only required columns, streams file hashes, and bounds the sparse matcher's working set with time slices (`SPARSE_CHUNK_PAIRS`) and batched crowd counts. Population-mode sweeps on multi-million-row data should use `--movers`, fewer workers, or a cropped region.

## Limits

- Strangers who share a route and a schedule (neighbours with the same commute) remain statistically indistinguishable from companions: the null scrambles who-travelled-with-whom across days but does not model shared routes. On a synthetic commuter fixture (80 people, 6 workplaces, 4 planted companions) the journey call flagged 5 pairs (1 planted, 4 route-sharing strangers) and the all-evidence call 2 (both strangers), against 331 for the uncrowded vote before journey scoring existed. Matched controls (same route, same time of day) would be needed to close this.
- Walking-pace companions (about 1 m/s) look like dwell under the default 1.3 m/s "stationary" band; the sweep grid includes a 0.4 m/s `still_speed` variant for them (on the commuter fixture two of four planted walkers still had no journey evidence at 120 s sampling and 15 m noise, because such displacements are not distinguishable from noise).

Event times are supporting observation bounds. Travel coordinates approximate shared locations, not route geometry. Co-dwell supports stationarity within sampled windows, not continuous occupation. Elliptical errors, 3D/altitude, HSMM and joint-arrival classification are not implemented. Polar data (beyond 80S/83.999N) is refused; MGRS uses WGS84 UTM with Norway/Svalbard exceptions, 100 m grid. Proximity CDF assumes a flat local prior and independent isotropic Gaussian errors. Days are counted by event start date. Focal tiles are processed independently, so a window cut by a tile edge relies on the margin for continuity. Real-data tests used an assumed 50 m @ 95% error for cell data because none was supplied.

References: [SciPy ncx2](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ncx2.html); [NGA MGRS/UTM](https://earth-info.nga.mil/index.php?action=coordsys&dir=coordsys).
