# Independent audit and generality study (October 2026)

Question: will this work on all types of datasets, for finding unknown objects that travel with a known one in a large haystack? Short answer for the repo as imported: no. For the current code: it works across a much wider range (sparse and dense cadence, any extent, dirty input, Python 3.12 and 3.14), with stated limits below.

## Method

- Own study: bundled benchmark and domain smoke tests re-run on Python 3.14 / pandas 3; ArcGIS "Find co-travelers" Camp Lemonnier geodatabase (1.29M phone pings, 1.06M vehicle points, Esri's own 100 ft / 10 s co-traveler layer as a weak reference, not ground truth); NOAA AIS 2023-01-01 (8.1M rows, US waters) with planted companions as known truth.
- Independent reviewers, each on a private copy with its own harness: Codex (`gpt-6-astra`) and a Sonnet 5.5 subagent, two rounds (original code, then the improved code).
- Fixes were verified against the reviewers' own repro cases, not only mine.

## Round 1 findings (original code)

1. Python 3.14 / pandas 3: elapsed time computed assuming nanosecond timestamps, so seconds were 1000x too small; recall 0 with exit code 0.
2. One bad coordinate, or any data spanning more than 1 degree, aborted the whole run (the real phone data has 27,520 rows from 7 phones outside the main area; AIS and aircraft data always span more).
3. A 15-minute window needing 3 fixes and no 10-minute gap discarded sparse or bursty data (84% of real phone windows "unknown"; zero co-travel events).
4. Acceptance needed 2 UTC days, so one-off single-day companions were never accepted.
5. Crowd discount 1/(1+crowd) made true companions in crowds mathematically unable to pass; co-dwell dominated accepted pairs.
6. Overtaking was scored as sustained co-travel; offset companions and followers (time lag) unreachable.
7. Input: naive timestamps, `+0000`, literal `NA`/`NULL` IDs, equivalent-time duplicates, silent empty results for bad focal IDs, stale outputs after failed reruns.
8. Scale: candidate search ignored the focal list and used the largest uncertainty in the window.

## What changed

See README and `skills/score-mover-associations/references/method.md`. In short: unit-independent time; region partition and overlapping tiles (antimeridian aware); sparse point-pair evidence; adaptive window, lag and radius scenarios; overtaking checked at both ends of the shared interval with velocity-fit uncertainty; focal-first bounded searches; input hardening; `adapt.py`; `sweep.py` with a null.

## Known limits (do not oversell)

- The family-wise test is conservative at 20 replicates on a single day of data; strong but not top-ranked companions can be left unflagged. More replicates and the ranked `sweep_pairs.csv` are the remedy. The day-permutation null needs at least 4 UTC days; shorter data use a time-shift null that does not preserve bursty observation windows.
- Calibration was validated on synthetic nulls only. Real data keeps individual habits; two movers with the same schedule and venue are indistinguishable from companions at wide radii. Check `best_radius_m` against the data's error.
- The Esri layer is another method's output. Agreement with it is indicative, not precision/recall. Phone accuracy (50 m at 95%) and AIS accuracy (15 m at 95%) are declared assumptions.
- Not implemented: elliptical or 3D errors, polar data, calibrated interaction probabilities, a fixed-time-of-day-aware null for single-day data, event day-splitting at midnight (days are counted by start date), exported start/end coordinates for window events are window centres.
- Slow motion (below about 1.3 m/s) is classified co-dwell; continuous multi-day shared stays count as one day.
